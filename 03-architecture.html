How the Follow-Up System is built: layering, the request pipeline, module dependencies, the entity-relationship model, the API surface, and key runtime sequences.

1 · Technology stack

RuntimeASP.NET Core 8 (.NET 8), single process, port 5080
LanguageC# 12; minimal-API endpoint classes
DatabasePostgreSQL 16/17
Data accessHand-written wire-protocol client (no ORM)
Web serverKestrel (container) / IIS in-process (Windows)
ClientZero-build vanilla-JS ES-module SPA
Real-timeServer-Sent Events + single-use tickets
AuthLocal username/password; PBKDF2 + HMAC token
LoggingSerilog (console + rolling file)
MapsLeaflet + OpenStreetMap/Nominatim
i18nBilingual en/ar, RTL, per-user language
PackagingMulti-stage Docker; IIS publish; uploads volume
Design stance. Nominal Clean-Architecture layering is present and enforced, but deliberately thin — most business logic lives in the API layer as transaction-script endpoint handlers issuing parameterized SQL. A full CQRS/mediator pipeline exists but is used for only two commands (complaint status change, lab status update). A rebuild may adopt the same pragmatic style or a richer domain model; the requirements in Document 01 are style-agnostic.

8 · Schema & integrity requirements

ConcernRequirement
ProvisioningSchema created/updated at startup: an idempotent base script plus tracked, transactional, advisory-locked run-once migrations. Migration strictness configurable.
KeysEvery table has a primary key. Lab code unique case-insensitively; one login per rep (partial unique); outsource unique per (visit_date, lab).
Referential integrityCASCADE for dependent detail (contacts, monthly samples, ledgers, preferences); SET NULL for test_setup→group; RESTRICT for history & signed records & user→rep.
EnumerationsCHECK constraints for lab status (8), visit (4), complaint (3), marketing (3), outsource (3), rep type (4), signature meaning (5), etc.
ConcurrencyOptimistic (row-version token) on labs & reps; 409 on stale. Others last-writer-wins.
MoneyAll monetary columns fixed numeric(18,2).
Audit immutabilityAppend-only via DB triggers refusing UPDATE/DELETE/TRUNCATE (binding even the owner); only a bounded, declared-cutoff retention purge may delete, and it audits itself first.
IndexesIndex hot FK/filter columns (visit dates, lab/rep ids, audit time, session, notification recipient). The rebuild should index complaint/marketing/contact lab_id (a known gap in the reference build).

9 · API surface

The API is a default-deny surface of 116 routes (all /api/* plus three /healthz/*). Every route has exactly one declared policy and one contract entry. Policy kinds:

Kind~CountMiddleware enforces
RequirePrivilege79Caller holds ≥1 listed privilege (else 403); handler usually re-checks + adds scope/ownership.
AuthenticatedOnly12Valid token only (reference/dropdown reads; e-sign re-auths inside).
SelfScoped9Valid token; handler scopes to the caller (notifications, own language/password).
Anonymous5Public: login + three health endpoints.
GuardedByHandler4No middleware privilege gate; a shared save handler is the only gate (lab/rep create/update).
ScopedOnly3Valid token; handler applies org scope, no privilege (labs list/read, daily suggest).

11 · Security architecture (summary)

ControlMechanism
PasswordsPBKDF2-SHA256, 100k iterations, per-user salt, constant-time compare.
TokensCompact signed payload (HMAC-SHA256), ~10h expiry; signing secret from environment; not a JWT, no refresh token.
SessionsDB session row; logout = revocation checked on every request; last-seen touched per request.
AuthorizationDefault-deny route table → privilege check → six-dimension scope + record ownership; privileges/scope re-read per request.
Grant safetyAnti-amplification on all user/role writes; self-role-change blocked; admin & in-use roles protected.
TransportOptional HSTS/HTTPS redirect; nosniff, frame-deny, no-referrer, COOP; CSP script-src 'self' (no inline code).
InjectionParameterized SQL; HTML output escaped (incl. email — build correction); content-sniffed, size-capped uploads; SSRF-guarded map resolver.
SecretsFiltered/masked on the wire; Oracle connection string never returned; Oracle SQL config-managed & allow-listed.
Data at restPasswords hashed; audit append-only. Gap to close: secrets and patient-shaped complaint fields stored in cleartext — the rebuild should add column/disk encryption and a patient-data decision (see SRS NFR-PRIV).
AuditabilityEvery state change audited atomically; trail immutable at the DB; e-signatures tamper-evident.
