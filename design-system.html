Design System

The Arfa Corporate Blue design language — a Fluent-inspired system for the Follow-Up B2B laboratory operations platform. This is a living style guide: every component below is rendered with the real production tokens. Use the Toggle theme button to preview light and dark.

Overview

Follow-Up is a dense, information-first back-office application: operators scan boards, tables, and dashboards all day. The design language is therefore built for clarity, density, and calm — a Microsoft-Fluent lineage (Segoe-like geometry, restrained depth, a confident corporate blue) tuned for long working sessions and full English/Arabic (RTL) parity.

How to use this document. Foundations define the tokens (color, type, spacing, elevation). Components show live specimens with their class names and the tokens they consume. The Token reference at the end is the copy-paste :root block — the single source of truth.

Design principles

PrincipleWhat it means in practice
Clarity over decorationFlat surfaces, hairline borders, one accent. Depth is used only to separate layers (header, cards, popovers), never for ornament.
Density with breathing roomCompact 13 px base UI text and tight tables, on an 4 px spacing grid so rhythm stays consistent even when packed.
One confident accentCorporate blue #0078D4 carries primary actions, active state, and links. Teal is the secondary/highlight accent. Everything else is neutral.
Status is a languageA fixed palette of semantic bg/ink pairs (success, warning, error, info, neutral, purple) used consistently for badges, banners, and KPIs.
Bilingual by constructionEvery component works in LTR English and RTL Arabic; the type system swaps Encode Sans ↔ Cairo automatically.
Accessible contrastText/background pairs meet WCAG AA; focus is always visible (teal ring); color is never the only signal (badges carry a dot, banners carry an icon + border).

App shell

Fixed blue header (64 px) → white sidebar rail (240 px) → canvas content: a page head card, a KPI row, then cards/tables. Collapsing the sidebar to 60 px slides the content margin.

Theming — light & dark

Dark mode is a token swap on body.dark-theme: canvas → near-black, surfaces → charcoal, the slate ramp inverts, and every semantic pair flips to deep-bg/light-ink. Brand blue and teal are unchanged so identity holds. All components inherit automatically because they consume tokens, never hard-coded hex. Try the toggle in the top bar.

Rule: components must reference tokens (var(--…)), never literal colors, so both themes and RTL stay correct with zero per-component work.

Setting dir="rtl" mirrors layout: nav active-bar flips to the right, header divider and badges mirror, text aligns right, and the font swaps Encode Sans → Cairo. Use logical properties (text-align:start, margin-inline) so mirroring is automatic.

Accessibility

AreaRequirement
ContrastText/background pairs meet WCAG AA (4.5:1 body, 3:1 large). Primary blue on white and white on primary blue both pass.
FocusAlways-visible focus: 2 px teal ring on inputs; keep a visible focus style on buttons/links/nav (do not remove outlines).
Not color-aloneStatus badges carry a dot; banners carry an icon + a left border; required fields carry an asterisk — meaning never rests on hue alone.
TargetsInteractive targets ≥ 32 px effective height; icon-only buttons get an accessible label.
KeyboardEvery action reachable and activatable by keyboard; modals trap focus and close on Esc; a central normalizer labels controls and makes non-native elements keyboard-activable.
MotionHonor prefers-reduced-motion.
